# تحليل شبكة LinkedIn + رسائل مخصصة لكل شخص

موقع ثابت بيشتغل على **GitHub Pages**، وكل المعالجة بتصير **داخل متصفحك**: بيقرا شبكتك من LinkedIn،
بينظّف ويصنّف كل شخص، بيرتّبهم بالأولوية حسب أهدافك، وبيكتب لكل واحد رسالة مخصصة (عربي + إنجليزي)
حسب **الشركة والقطاع والمنصب** وحسب **إذا تواصلتوا قبل أو لا**.

ما في سيرفر. البيانات ما بتطلع من جهازك، إلا إذا استخدمت ميزات الذكاء الاصطناعي، وقتها بينبعت لـ OpenAI
بس الي بيلزم لكتابة الرسالة.

## 1) من وين بتيجي البيانات

| الطريقة | متى | ليش |
|---|---|---|
| **ملف الـ Export الرسمي** | أول مرة | أسرع وأأمن طريقة لسحب آلاف الأشخاص وكل الرسائل دفعة وحدة |
| **إضافة المتصفح (Chrome أو Firefox)** | كل مرة بعدها | بيسحب بس الجديد من آخر مزامنة: أشخاص جدد ورسائل جديدة |

### ليش مش تسجيل دخول بالإيميل وكلمة المرور؟
- الـ API الرسمي لـ LinkedIn ما بيعطي قائمة الـ connections ولا الرسائل لأي تطبيق عادي.
- موقع على GitHub Pages ما بيقدر يكلّم linkedin.com مباشرة (المتصفح بيمنع هاد، CORS)،
  وتسجيل الدخول الآلي بيوقف عند التحقق الثنائي والـ captcha، وبيعرّض الحساب للحظر.
- الـ Extension بيستخدم **جلستك انت** وانت مسجّل دخول، فما في كلمة مرور بتنحفظ بأي مكان.

### أول مرة: ملف الـ Export
1. LinkedIn ← صورتك ← **Settings & Privacy** ← **Data privacy** ← **Get a copy of your data**
2. اختار **Connections** و **Messages** و **Invitations** و **Shares** (منشوراتك، لقسم المحتوى) ← **Request archive**
3. بيوصلك إيميل فيه رابط التحميل (ممكن ياخذ لـ 24 ساعة مع الرسائل)
4. بالموقع، صفحة **البيانات**: اسحب ملف الـ `.zip` كما هو

الملف بينقرا بالخلفية (Web Worker)، فالصفحة ما بتعلق حتى لو الملف كبير.

### بعدها: إضافة المتصفح (Chrome أو Firefox)

**Chrome** (و Edge و Brave):
1. من صفحة **البيانات** اضغط **تحميل لـ Chrome** وفك الضغط بمجلد ثابت
2. افتح `chrome://extensions`، فعّل **Developer mode**، واضغط **Load unpacked** واختار المجلد
3. تأكد إنك مسجّل دخول على linkedin.com بنفس المتصفح
4. ارجع للموقع واضغط **مزامنة الآن**

**Firefox** (140 أو أحدث، أو 142 على أندرويد): من صفحة **البيانات** اضغط **تحميل لـ Firefox** وبتنزل `linkedin-network-extension.xpi`.
- **إذا الملف موقّع من Mozilla:** اضغط الزر من فايرفوكس نفسه، ووافق على التركيب. التركيب دائم.
- **إذا مش موقّع:**
  - على Firefox Developer Edition أو Nightly أو ESR: خلّي `xpinstall.signatures.required = false` بـ `about:config`، وبعدها من `about:addons` ← الترس ← **Install Add-on From File**. التركيب دائم.
  - على فايرفوكس العادي: `about:debugging#/runtime/this-firefox` ← **Load Temporary Add-on**. بينشال لما تسكّر المتصفح.

> فايرفوكس ما بيسمح لصفحة ويب تحكي مع إضافة مباشرة، فنسخة فايرفوكس فيها content script صغير على صفحة الأداة بس، بينقل الرسائل بين الصفحة والإضافة.

#### توقيع نسخة فايرفوكس تلقائيًا
الـ workflow بيوقّع الـ `.xpi` من Mozilla (unlisted، يعني مش منشور بالمتجر) لما يلاقي مفاتيح AMO:
1. سجّل دخول على [addons.mozilla.org](https://addons.mozilla.org) بحساب Firefox.
2. افتح [Manage API Keys](https://addons.mozilla.org/developers/addon/api/key/)، وافق على الاتفاقية، واضغط **Generate new credentials**.
3. بالـ repo على GitHub: **Settings ← Secrets and variables ← Actions ← New repository secret**، وضيف:
   - `AMO_JWT_ISSUER` = قيمة **JWT issuer**
   - `AMO_JWT_SECRET` = قيمة **JWT secret**
4. من **Actions ← Test and deploy to GitHub Pages ← Run workflow** شغّله مرة على `main`.

بعدها كل تعديل على الإضافة بينوقّع لحاله بنسخة جديدة (`1.4.0.<رقم التشغيل>`). ولما الإضافة ما تتغير، الـ workflow بيحتفظ بالملف الموقّع من الموقع المنشور.

كيف بيشتغل:
- بيفتح تبويب LinkedIn بالخلفية وبيقرا بنفس الطلبات الي LinkedIn نفسه بيعملها. المزامنة **قراءة بس**.
- بيسحب الأشخاص من الأحدث للأقدم، وبيوقف أول ما يوصل لآخر شخص عندك من قبل (مع هامش يوم).
  خيار **"حدّث بيانات وصور كل الأشخاص"** بيمر على كل الشبكة عشان يحدّث الـ Headline والصور.
- للرسائل بيعرف طلبات LinkedIn من صفحة `linkedin.com/messaging`، وإذا كانت قديمة بيفتح تبويب رسائل جديد.
  القراءة بتبدأ دايمًا من الأحدث، وبيسحب بس المحادثات الي صار فيها جديد.
- إذا فشلت الرسائل، الأشخاص الجدد بينحفظوا عادي، والسبب بيطلع كملاحظة تحت المزامنة.
- الصور بتنحفظ كروابط بس بـ `photos.yaml`، وإذا ما في صورة بتطلع الحروف الأولى من الاسم.
- ببطء (ثانية لثانيتين بين كل طلب) وعلى دفعات، وبيحفظ مكانه بعد كل دفعة. إذا انقطع بيكمل من وين وقف.
- نسخة الإنتاج بتقبل تحكي بس مع رابط الموقع الرسمي، والنسخة المحلية بس مع `localhost`.
- **منشوراتك** (من قسم إنتاج المحتوى ← منشوراتي): بيقرأ منشوراتك انت بس من صفحة الـ Activity، مع عدد التفاعلات والتعليقات وإعادة النشر، 20 منشور بكل صفحة وبهدوء. أول مرة بيسحب الكل، وبعدها الجديد وأرقام آخر 90 يوم. بيندمج مع `Shares.csv` بدون تكرار. المشاهدات (Impressions) غالبًا ما بتيجي، فبتدخّلها بإيدك.

> استخدام أي أداة آلية تقنيًا ضد شروط LinkedIn. الـ Extension بيقلل الخطر قدر الإمكان (قراءة بس، بطيء،
> بجلستك)، بس الخطر صغير مش صفر.

حدود معروفة: LinkedIn بيعطي للأشخاص الجدد الـ Headline بس، فالشركة بتنستنتج منه إذا مكتوب "Title at Company".
والـ endpoints الداخلية لـ LinkedIn بتتغير كل فترة؛ إذا تغيرت، المزامنة بتوقف برسالة واضحة والـ Export بيضل شغّال.

## 2) الحفظ والاسترجاع

- كل شي بينحفظ **تلقائيًا** بالمتصفح (IndexedDB، بيتحمل أحجام كبيرة).
- **تنزيل ملف الحفظ** بيعطيك `zip` واحد فيه ملف YAML لكل نوع بيانات:

| الملف | المحتوى |
|---|---|
| `meta.yaml` | النسخة، صاحب الحساب، **نقطة آخر مزامنة**، معلومات الـ Export |
| `profile.yaml` | بروفايلك، أهدافك، أوزان النقاط، تصحيحات القطاعات |
| `connections.yaml` | كل الأشخاص من كل المصادر |
| `messages.yaml` | كل الرسائل |
| `invitations.yaml` | الدعوات |
| `tracking.yaml` | المتابعة (الحالة، تاريخ الإرسال، الرد، الملاحظات) + سجل التواصل الخارجي |
| `ai.yaml` | الرسائل والتصنيفات الي عملها الذكاء الاصطناعي |
| `content.yaml` | منشوراتك وأرقامها، الأفكار والمسودات ونسخها، استراتيجية المحتوى، وإعدادات المحتوى |
| `images/*.webp` | صور المنشورات (مضغوطة) |

ارفع نفس الملف لاحقًا (أو على جهاز ثاني) وبتكمل من حيث وقفت. المزامنة الجاية بتبدأ من النقطة المحفوظة.
مفتاح OpenAI **ما بينحفظ** بهاد الملف أبدًا.

## 3) الذكاء الاصطناعي (OpenAI)

صفحة **الذكاء الاصطناعي**: حط مفتاح API واختار الموديل (الافتراضي `gpt-4.1-mini`، وما بدّه توثيق للمنظمة).
إذا الموديل الي اخترته مش متاح لحسابك، الأداة بتكمل لحالها بـ `gpt-4.1-mini` وبتوقف الدفعة من أول خطأ ثابت بدل ما تكرره لكل شخص.

- **رسائل مخصصة**: لأي شخص من صفحته، أو دفعة وحدة لكل أولوية A. الرسالة بتاخذ بعين الاعتبار
  دوره وشركته وقطاعه ووضع التواصل وآخر رسائل بينكم، وبالعامية الأردنية مش ترجمة حرفية.
- **تصنيف المجهولين**: الأشخاص الي مستواهم أو تخصصهم أو قطاعهم `Unknown` بيتصنفوا من قوائم ثابتة،
  والنتيجة بتنعلّم `AI` بعمود الأدلة.
- **قوالب حسب الهدف**: نسخة AI من أي قالب (إحالة، سؤال عن وظيفة، نصيحة، تعارف، شكر).
- **تحليل المحادثات**: وين وقفتوا، نبرة الشخص، الخطوة الجاية، ورد مقترح. لشخص واحد من صفحته، أو دفعة وحدة
  للمحادثات الي بانتظار ردك. التحليل بيتعلّم "قديم" إذا وصلت رسائل جديدة بعده.
- **اقتراحات الشبكة**: شركات جديدة وأنواع ناس تضيفهم وخطوات للأسبوع، مع روابط بحث LinkedIn. ما بتنبعت أسماء أشخاص.

الأمان:
- المفتاح بيضل بالمتصفح (sessionStorage، أو localStorage إذا اخترت "تذكّر")، وبينبعت لـ `api.openai.com` بس.
- سياسة CSP بالموقع بتمنع أي اتصال لأي مكان ثاني.
- اللي بينبعت: معلوماتك المهنية، واسم الشخص الأول ومنصبه وشركته، وآخر كم رسالة بينكم. **ما بينبعت** إيميل ولا رابط بروفايل.

## 4) الصفحات

| الصفحة | المحتوى |
|---|---|
| **البيانات** | رفع الـ Export، المزامنة، الحفظ والاسترجاع، استيراد سجل خارجي أو تقرير Excel قديم أو `my_profile.json` |
| **جهات الاتصال** | كل شخص مرتّب بالأولوية، فلاتر وبحث ووسوم، وصفحة لكل شخص فيها الرسائل (قواعد / AI) وقوالب حسب الهدف وتحليل المحادثة والمتابعة والملاحظات |
| **الشركات** | صف لكل شركة: عدد معارفك، أفضل نقطة دخول، أصحاب القرار |
| **المؤشرات** | نمو الشبكة، نشاط الرسائل، نسبة الرد، وتوزيعات حسب المستوى والتخصص والقطاع والشركة والدولة والوسوم + **تقرير Excel كامل** |
| **الإرسال** | قائمة رسائل تراجعها وتعدّلها قبل ما تبعتها، وطلبات تواصل لناس من نتائج بحث LinkedIn |
| **إنتاج المحتوى** | تحليل منشوراتك وملفك واستراتيجية وأفكار بالذكاء الاصطناعي، لوحة أفكار ومسودات، محرر مع معاينة LinkedIn وفحص قبل النشر وأدوات تحسين ونسخ سابقة، صور بالذكاء الاصطناعي أو رفع صورة، كاروسيل PDF، استطلاعات، تقويم وخطة نشر، وأرقام التفاعل لكل منشور. النشر دايمًا بإيدك |
| **الفرص والفجوات** | فجوات الشبكة مقارنة بأهدافك، أشخاص تتابع أو ترجع تحكي معهم أو تبدأ معهم، شركات تركّز عليها، واقتراحات AI |
| **ملفي وأهدافي** | بروفايلك، التوقيع، التخصصات والقطاعات والشركات المستهدفة، أوزان النقاط، تصحيح القطاعات |
| **الذكاء الاصطناعي** | المفتاح والموديل والميزات |
| **جودة البيانات** | شو انقرا، شو ناقص، وشو اتصلّح |

### الإرسال من الأداة
- من تفاصيل أي شخص، اضغط **جهّز للإرسال** تحت أي رسالة. أو من جهات الاتصال اختار فلتر ونوع رسالة واضغط **جهّز رسالة للنتيجة** (أول 25).
- بصفحة **الإرسال** بتراجع كل رسالة وبتعدّلها، وبتأكد إنك راجعتها، وبعدها بتبعت.
- لطلبات التواصل: افتح بحث أشخاص على LinkedIn، واضغط **اسحب الأشخاص من صفحة البحث**، واختار مين، واكتب نوت (`{name}` بتصير الاسم الأول).
- الأمان: واحد كل 45 لـ 120 ثانية، بحد أقصى 25 رسالة و20 طلب باليوم (100 و80 بالأسبوع).
  الإرسال بيوقف لحاله إذا LinkedIn طلب تحقق أو قال في طلبات كثير، أو بعد 3 فشل ورا بعض.
- كل رسالة بتنبعت بتتسجل "Message sent" بالمتابعة. وبدون الـ Extension في **انسخ وافتح** للإرسال بإيدك.
- كبسة **افتح المحادثة** بتفتح المحادثة مع الشخص على LinkedIn إذا في وحدة، و**افتح البروفايل** بتفتح بروفايله.

> الإرسال الآلي ضد شروط LinkedIn، وممكن يوقف حسابك مؤقتًا إذا كان كثير أو متشابه. الحدود محافظة، بس الخطر مش صفر.

المتابعة الي بتسجلها (مثلًا "Message sent" بتاريخ) **بتأثر على وضع التواصل**: الشخص بيصير "بانتظار رد"
وما بتنكتبله رسالة تعريف مرة ثانية.

أي قائمة (جهات الاتصال بعد الفلترة، الشركات، الفجوات، الاقتراحات، وكل توزيع بالمؤشرات) إلها زر **CSV | Excel**.
الوسوم والملاحظات بتنحفظ بـ `tracking.yaml`، ونتائج الـ AI كلها بـ `ai.yaml`.

## 5) كيف يشتغل التصنيف والنقاط

نفس منطق النسخة السابقة بالضبط، منقول لـ TypeScript:

- **المستوى**: قراءة قواعدية للمسمى من الأعلى للأدنى، مع معالجة فخاخ "Product/Project/Account Manager".
- **التخصص**: مطابقة كلمات موزونة بالعربي والإنجليزي، والأقوى بيفوز.
- **القطاع**: من اسم الشركة + شركات معروفة + تصحيحاتك. أي شي مش أكيد بيضل `Unknown`.
- **النقاط**: مجموع موزون وشفاف، وسبب النقاط لكل شخص ظاهر بـ `Score Breakdown`.
- **وضع التواصل**: Cold / Reconnect / Nudge، وكل وضع إله رسالة مختلفة.

## 6) التطوير

```bash
npm ci
npm run dev          # http://localhost:5173
npm test             # vitest
npm run build        # الموقع + الـ Extension داخل dist/
```

الإضافة إلها نسختين، كل وحدة بـ ID مختلف، فبتقدر تركّبهم مع بعض. كل أمر بيبني نسخة Chrome ونسخة Firefox:

| النسخة | الأمر | مجلد Chrome | مجلد Firefox | بتشتغل مع |
|---|---|---|---|---|
| محلية | `npm run extension:local` | `dist-extension/local` | `dist-extension/local-firefox` | `http://localhost:5173` و `4173` |
| إنتاج | `npm run extension:production` | `dist-extension/production` | `dist-extension/production-firefox` | موقع GitHub Pages |

الإعدادات بملف `extension/targets.json`. الموقع بيختار النسخة لحاله: على `localhost` بيحكي مع المحلية، وغير هيك مع نسخة الإنتاج.
بعد أي تعديل على الإضافة، أعد البناء واضغط زر التحديث ↻ عليها بـ `chrome://extensions`، أو **Reload** بـ `about:debugging` على فايرفوكس.

النشر تلقائي: أي push على `main` بيشغّل الاختبارات وبيبني وبينشر على GitHub Pages.
فعّل مرة وحدة: **Settings ← Pages ← Source: GitHub Actions**.

بنية المشروع:

```
src/
  core/        المنطق: تنظيف، تصنيف، نقاط، سجل التواصل، رسائل، دمج البيانات
  io/          قراءة الـ Export، ملف الحفظ (zip + YAML)، IndexedDB، Excel، Web Worker
  ai/          OpenAI: المفتاح، الطلبات، الرسائل، التصنيف
  linkedin/    الربط مع الـ Extension
  ui/          الواجهة
extension/     إضافة المتصفح (Manifest V3) لـ Chrome و Firefox
scripts/       بناء الإضافة
samples/       بيانات وهمية للتجربة والاختبارات
tests/
```

للتجربة بدون بياناتك: اعمل zip لمجلد `samples/export_example` وارفعه.
